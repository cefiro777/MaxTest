# MaxTest — детальный план реализации (средний уровень)

Версия плана: 1.0 · Дата: 2026-07-21
Окружение: Windows 10 Pro x64, Python 3.10.6, PyQt6, PyInstaller (`--onedir`)

---

## 0. Рамки проекта

**В скоупе (средний уровень):**
конструктор тестов с картинками, 5 типов вопросов, перемешивание и выборка из банка,
таймер, гибкие правила оценки (веса, частичный балл, шкала), разделы, локальное хранение
результатов, отчёты в Excel, разбор ошибок.

**Вне скоупа (осознанно не делаем):** режим киоска, шифрование результатов, сеть,
роли/пароли, видео/аудио, LaTeX, адаптивное тестирование, импорт из Word.

**Целевые пользователи:** 1 администратор (создаёт тесты, смотрит отчёты) и ~20 сотрудников
(проходят тест на одном общем ПК раз в год).

## 2. Формат файла теста `.qtest`

ZIP-архив (как `.docx`):

```
demo.qtest
├── manifest.json
└── media/
    ├── img_a1b2c3.jpg
    └── img_d4e5f6.png
```

### 2.1 manifest.json — схема

```jsonc
{
  "schema_version": 1,
  "id": "e2f1...uuid4",              // неизменный ID теста
  "title": "Аттестация электромонтёров 2026",
  "description": "Годовая проверка знаний",
  "author": "Иванов И.И.",
  "created_at": "2026-07-21T10:00:00",
  "modified_at": "2026-07-21T12:30:00",
  "revision": 3,                      // +1 при каждом сохранении, пишется в результат

  "settings": {
    "shuffle_questions": true,
    "shuffle_options": true,
    "questions_to_ask": 20,           // null = все вопросы банка
    "selection_mode": "by_section",   // "all" | "random" | "by_section"
    "time_limit_sec": 1800,           // null = без ограничения
    "time_limit_per_question_sec": null,
    "allow_back": false,              // навигация назад
    "show_result_to_user": true,      // показывать ли балл сотруднику
    "show_review_to_user": false      // показывать ли разбор ошибок
  },

  "grading": {
    "multi_mode": "partial",          // "all_or_nothing" | "partial"
    "partial_penalty": true,          // минус за лишний выбор, не ниже 0
    "text_manual_review": true,       // помечать текстовые ответы на ручную проверку
    "scale": {
      "type": "pass_fail",            // "pass_fail" | "five_point" | "custom"
      "thresholds": [                 // в ЦЕЛЫХ процентах, по убыванию
        { "min_percent": 70, "label": "Сдал",   "passed": true },
        { "min_percent":  0, "label": "Не сдал", "passed": false }
      ]
    }
  },

  "sections": [
    { "id": "s1", "title": "Охрана труда", "take_count": 10 },
    { "id": "s2", "title": "Оборудование",  "take_count": 10 }
  ],

  "questions": [
    {
      "id": "q_7f3a",                 // uuid4, НИКОГДА не меняется
      "section_id": "s1",
      "type": "single",               // single|multi|text|matching|ordering
      "text": "Что делать при обнаружении оголённого провода?",
      "image": "media/img_a1b2c3.jpg",// null если нет
      "weight": 1.0,                  // вес вопроса в баллах
      "options": [
        { "id": "o1", "text": "Обесточить участок", "correct": true,  "no_shuffle": false },
        { "id": "o2", "text": "Изолировать вручную", "correct": false, "no_shuffle": false },
        { "id": "o3", "text": "Все перечисленное",   "correct": false, "no_shuffle": true }
      ],
      "answer_text": null,            // для type=text: список эталонов
      "pairs": null,                  // для type=matching
      "order": null,                  // для type=ordering
      "explanation": "ПОТЭЭ п. 3.2"   // показывается в разборе
    }
  ]
}
```

### 2.2 Поля под конкретные типы

| Тип | Ключевые поля | Формат |
|---|---|---|
| `single` | `options[]` | ровно один `correct: true` |
| `multi` | `options[]` | ≥1 `correct: true` |
| `text` | `answer_text` | `{"accepted": ["220 В", "220в"], "match": "normalized"}` где `match` ∈ `exact`/`normalized`/`contains` |
| `matching` | `pairs` | `[{"id":"p1","left":"Пред-ль","right":"Ток"},…]` — правые части перемешиваются |
| `ordering` | `order` | `[{"id":"i1","text":"Шаг 1"},…]` — правильный порядок = порядок в массиве |

### 2.3 Правила формата (не нарушать)

1. `schema_version` пишется всегда; загрузчик умеет мигрировать `v1 → vN`.
2. Все `id` — стабильные uuid4-хвосты, генерируются один раз при создании объекта.
   Правильность привязана к `id`, **никогда** к индексу в массиве.
3. Пути к картинкам — только относительные внутри архива (`media/...`).
   Абсолютных путей в manifest быть не может в принципе.
4. Имя файла картинки — хеш содержимого (`img_<md5[:8]>.jpg`): дедупликация «бесплатно».
5. Сохранение — атомарное: пишем во временный файл рядом, `os.replace()` поверх исходного.
   Иначе аварийное завершение при сохранении убивает тест целиком.

## 3. Модель данных (core/models.py)

```python
@dataclass
class Option:
    id: str
    text: str
    correct: bool = False
    no_shuffle: bool = False

@dataclass
class Question:
    id: str
    type: QuestionType
    text: str
    weight: float = 1.0
    section_id: str | None = None
    image: str | None = None            # относительный путь в бандле
    options: list[Option] = field(default_factory=list)
    answer_text: TextAnswer | None = None
    pairs: list[MatchPair] | None = None
    order: list[OrderItem] | None = None
    explanation: str = ""

@dataclass
class Test:
    id: str
    title: str
    settings: TestSettings
    grading: GradingRules
    sections: list[Section]
    questions: list[Question]
    revision: int = 1
```

Плюс `Bundle` — обёртка над открытым `.qtest`: хранит `Test` + доступ к медиа
(`get_image_bytes(path) -> bytes`), умеет `save(path)` и `add_image(src_file) -> rel_path`.

Отдельно — «сессия попытки» (генерируется при старте, никогда не хранится в тесте):

```python
@dataclass
class AttemptPlan:
    seed: int                                  # для воспроизводимости
    question_ids: list[str]                    # порядок показа, уже отобранный
    option_order: dict[str, list[str]]         # q_id -> порядок option_id
```

`AttemptPlan` сохраняется в результат — только так экран разбора покажет ровно то,
что видел человек.

## 4. Хранилище результатов (SQLite)

Файл: `%APPDATA%\MaxTest\results.db`. При каждом старте — копия в
`%APPDATA%\MaxTest\backup\results_YYYYMMDD.db` (хранить последние 30).

```sql
CREATE TABLE employees (
    id INTEGER PRIMARY KEY,
    full_name TEXT NOT NULL,
    position TEXT,
    department TEXT,
    active INTEGER DEFAULT 1
);

CREATE TABLE attempts (
    id INTEGER PRIMARY KEY,
    employee_id INTEGER REFERENCES employees(id),
    employee_name TEXT NOT NULL,      -- денормализация: снимок ФИО на момент теста
    test_id TEXT NOT NULL,
    test_title TEXT NOT NULL,
    test_revision INTEGER NOT NULL,
    started_at TEXT NOT NULL,
    finished_at TEXT,
    finish_reason TEXT,               -- 'completed' | 'timeout' | 'aborted'
    seed INTEGER,
    score REAL, max_score REAL, percent REAL,
    grade_label TEXT, passed INTEGER,
    needs_review INTEGER DEFAULT 0    -- есть текстовые ответы на ручную проверку
);

CREATE TABLE answers (
    id INTEGER PRIMARY KEY,
    attempt_id INTEGER REFERENCES attempts(id) ON DELETE CASCADE,
    question_id TEXT NOT NULL,
    question_text TEXT NOT NULL,      -- снимок текста вопроса
    shown_index INTEGER,              -- какой по счёту показан
    raw_answer TEXT,                  -- JSON: сырой ответ пользователя
    is_correct INTEGER,               -- 0/1/NULL (NULL = ждёт ручной проверки)
    score REAL, max_score REAL,
    manual_override INTEGER DEFAULT 0
);
```

**Денормализация намеренная:** тест могут отредактировать после аттестации, а отчёт
за прошлый год обязан остаться правдой. Храним снимок текста и `test_revision`.

## 5. Движок оценки (core/grader.py)

Чистая функция, без GUI и без БД:

```python
def grade_question(q: Question, raw_answer, rules: GradingRules) -> QuestionResult
def grade_attempt(test, plan, answers, rules) -> AttemptResult
```

### 5.1 Алгоритмы по типам

**single** — `raw = option_id`; балл = `weight` если `correct`, иначе 0.

**multi** — пусть `C` — множество правильных, `A` — выбранных, `W` — неправильных всего.
- `all_or_nothing`: `weight` если `A == C`, иначе 0.
- `partial`: `hits = |A ∩ C|`, `misses = |A \ C|`
  `score = weight * max(0, hits/|C| - misses/max(1,W))`
  Так «отметить всё» даёт ровно 0 — стратегия обнуляется автоматически.

**text** — нормализация → сравнение со списком эталонов:
```python
def normalize(s): 
    s = s.strip().lower().replace("ё", "е")
    s = re.sub(r"\s+", " ", s)
    s = s.replace(",", ".")            # 3,5 == 3.5
    return s
```
Режим `contains` — эталон должен входить в ответ (для развёрнутых ответов).
Если `text_manual_review = true` — результат `is_correct = NULL`, попытка помечается
`needs_review`, балл начисляется предварительно и может быть изменён вручную.

**matching** — балл за каждую верную пару: `weight * correct_pairs / total_pairs`.

**ordering** — доля соседних пар в правильном относительном порядке
(мягче, чем «всё или ничего», и устойчивее к сдвигу на одну позицию).

### 5.2 Шкала

```python
percent = round(score / max_score * 100)          # ЦЕЛОЕ число
for t in sorted(thresholds, key=lambda x: -x.min_percent):
    if percent >= t.min_percent: return t
```
Проценты — только целые, пороги — только целые. Никаких сравнений float’ов
на границе (`0.7 != 0.7` в двоичной арифметике — классический промах на балл).

### 5.3 Тесты движка (обязательны до UI)

Минимум 25 pytest-кейсов: пустой ответ, все варианты выбраны, ни одного,
частичный, вопрос с весом 0, `max_score == 0` (деление на ноль!),
границы шкалы 69/70/71, «ё/е», лишние пробелы, запятая в числе,
ordering со сдвигом на одну позицию.

Прогресс пишется в `%APPDATA%\MaxTest\progress\<id>.json`, а не в базу: запись в
SQLite каждые 15 секунд ради данных, живущих минуты, — лишний риск для базы с
результатами. При старте программа предлагает продолжить оборванную попытку.

**DoD:** тест проходится целиком, ответы сохраняются в БД, повторный проход другим
сотрудником добавляет запись, а не затирает.

**Подводные камни:**
- **Ответ хранится по `option_id`, не по позиции.** При `shuffle_options` любая
  привязка к индексу — гарантированный неверный подсчёт.
- **`no_shuffle` для «все перечисленное»/«ничего из перечисленного».** Иначе такой
  вариант окажется вторым и потеряет смысл.
- **Часы.** Таймер считайте по `time.monotonic()`, а не по `datetime.now()` —
  иначе перевод системного времени ломает отсчёт.
- **Выборка меньше банка.** Если в разделе просят 10 вопросов, а есть 7 — берите
  сколько есть и явно сообщайте в валидации, а не падайте.
- **Двойной клик по «Далее»** — блокируйте кнопку на время перехода.
- **Alt+F4 посреди теста.** Обрабатывайте `closeEvent`: подтверждение + запись
  попытки со статусом `aborted`. Молча потерянная попытка — худший вариант.

| 4.6 | pytest-набор по §5.3 | ✅ |

Ключевое решение: в попытку сохраняется **снимок шкалы** (`attempts.scale`), а в
каждый ответ — тип вопроса, раздел и правильный ответ строкой. Пересчёт после
ручной проверки не должен зависеть от файла `.qtest`, который к тому моменту
могут изменить, потерять или унести на другой компьютер.

Схема БД теперь умеет догонять себя: `_migrate()` добавляет недостающие колонки
в базы прежних версий (`CREATE TABLE IF NOT EXISTS` этого не делает), а индексы
создаются после миграции.

**DoD:** тесты зелёные, балл на экране совпадает с расчётом руками на бумаге.

**Подводные камни:**
- `max_score` считается по **показанным** вопросам, а не по всему банку. При выборке
  10 из 50 максимум — 10, иначе все получат 20%.
- Вопрос с `weight = 0` (информационный) не должен попадать в знаменатель.
- Пересчёт после ручной проверки обязан обновлять `percent`, `grade_label`, `passed`
  одной транзакцией — иначе получите попытки с баллом 90% и меткой «Не сдал».

Что вскрылось при сборке:

* **Стартовый скрипт.** PyInstaller запускает его как модуль верхнего уровня,
  без пакета, поэтому `maxtest/__main__.py` с относительным импортом падал ещё
  до создания окна — а в оконной сборке ошибка не видна вообще, процесс просто
  зависает. Добавлен `run_maxtest.py` с абсолютным импортом и тесты-стражи в
  `tests/test_entrypoint.py`.
* **`collect_dynamic_libs("PyQt6")` тащит все DLL Qt подряд** (Qml, Quick,
  Designer, кодеки, `opengl32sw.dll`) — сборка весила 206 МБ вместо 96 МБ.
  Штатный хук PyInstaller собирает только нужное.
* **Падение при закрытии программы** (найдено при ручной проверке 2026-07-22).
  Счётчик «Проверка ответов» обновлялся по сигналу `destroyed` окна
  прохождения, но Qt уничтожает дочерние окна уже ПОСЛЕ выхода из `app.exec()`,
  когда соединение с SQLite закрыто, — в лог падала
  `sqlite3.ProgrammingError: Cannot operate on a closed database`.
  Исправлено втройне: счётчик обновляется по активации главного окна
  (`QEvent.WindowActivate`), `AppWindow.shutdown()` закрывает дочерние окна до
  закрытия базы, а `Storage.is_open` страхует обработчики. Регрессия закрыта
  тестом `test_closing_app_after_attempt_does_not_touch_closed_db`.
* **Галочка ручной проверки была мёртвой** (найдено при ручной проверке
  2026-07-22). В редакторе текстового вопроса она лишь отражала настройку
  теста и не нажималась. Добавлено поле `Question.manual_review`
  (`None` — как в тесте, `True`/`False` — решение для вопроса), схема поднята
  до версии 2 с миграцией-заглушкой: файлы версии 1 читаются как прежде.
* **Диагностика в сборке.** Добавлена команда `MaxTest.exe --selfcheck`:
  плагины Qt, форматы изображений, права на запись. Отчёт пишется в файл и
  показывается диалогом, потому что консоли у оконной сборки нет.

**Подводные камни:**
- **Первую сборку делайте в конце фазы 1**, а не в конце проекта. Проблемы
  PyInstaller всегда всплывают позже, чем удобно.
- **Антивирус.** `--onefile` регулярно ловит ложное срабатывание Defender.
  `--onedir` + папка в исключениях — надёжнее.
- **`Program Files` только на чтение.** Любая запись рядом с `.exe` упадёт по правам
  у сотрудника без админа.
- **Необработанное исключение = молчаливое закрытие окна** в собранном GUI-приложении
  (консоли нет). Без `excepthook` вы никогда не узнаете, почему у сотрудника «всё
  пропало».
